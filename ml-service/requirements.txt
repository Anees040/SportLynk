# SportLynk ML service — Python dependencies
#
# EXACT PINS, NOT RANGES.
#
# A joblib artifact is a pickle of live scikit-learn objects. It is NOT portable
# across sklearn versions: loading a model trained on a different version either
# warns and behaves subtly differently, or fails outright. `scikit-learn>=1.9`
# would therefore mean "this model may or may not reproduce", which is not
# something a model card can claim. reports/model_card.md names the versions that
# produced each artifact, and /health reports the versions of the running process,
# so a mismatch is visible rather than mysterious.
#
# Every pin below was verified to have a cp314 wheel for the installed Python
# (3.14.4) — no C compiler is needed to install this file on Windows.
#
# Install:
#   cd ml-service
#   python -m venv .venv
#   .\.venv\Scripts\Activate.ps1
#   pip install -r requirements.txt
#
# TRANSITIVE dependencies (scipy, pydantic, starlette, threadpoolctl, ...) are not
# pinned here; this is a requirements file, not a lock file. scipy in particular
# affects sklearn's numerics, so Wave B's training run records the FULL resolved
# environment — `pip freeze > reports/requirements.lock.txt` — alongside the
# metrics. That is the artifact that makes a training run reproducible, and it
# belongs with the evidence rather than in the install contract.

# ── Serving ─────────────────────────────────────────────────────────────
fastapi==0.141.1
uvicorn==0.52.4
# NOTE: plain uvicorn, not uvicorn[standard]. The extras are uvloop (no Windows
# support), httptools, websockets and watchfiles — none of which this service
# uses. If you want `uvicorn --reload` during development, `pip install watchfiles`
# separately; run_dev.ps1 deliberately runs without --reload so the documented
# command has no optional dependency.

# ── Modelling ───────────────────────────────────────────────────────────
scikit-learn==1.9.0
pandas==3.0.5
numpy==2.5.2
joblib==1.5.3

# ── Assistant NLU (S.6) ─────────────────────────────────────────────────
dateparser==1.4.2
# FALLBACK ONLY, and pinned for two separate reasons.
#
# core/entities.py resolves dates with its own regex + calendar rules first: every
# form the corpus and the exam actually contain ("kal", "parso", "is weekend",
# "30/08", "friday ko", "2 din baad") is handled in code, deterministically, in
# Asia/Karachi. dateparser is consulted ONLY for a leftover date FRAGMENT the rules
# did not claim, which is why entities.self_check() passes with it uninstalled —
# the extractor degrades, it does not break.
#
# The pin matters because this package's behaviour IS its data: it ships language
# files and settings whose parsing of an ambiguous "30/08" (DMY vs MDY) is a
# version-dependent default, and a silent minor bump could change a resolved
# booking date. Same argument as the sklearn pin above, one layer out.
#
# Its cost is paid at BOOT, not per request: the first parse loads language data
# and was measured at 8,254 ms (1-7 ms after). routers/nlu.warm() calls
# entities.warm() in main.py's lifespan for exactly that reason — see the 50 ms
# per-parse budget in routers/nlu.py.
